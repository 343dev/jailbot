# 03 — Отклонять невыполнимые явно запрошенные режимы до запуска Docker

**What to build:** когда пользователь явно запрашивает workdir, SSH forwarding или задаёт значение option, Jailbot либо гарантирует возможность выполнить запрос, либо немедленно завершает работу с понятной диагностикой до обращения к Docker.

**Blocked by:** 01 — Создать строгий process-level контур тестирования CLI.

**Status:** done

- [x] Пустой, отсутствующий, несуществующий, недоступный или не являющийся каталогом `--workdir` приводит к ненулевому exit status до вызова Docker.
- [x] Ошибка `--workdir` называет проблемное значение и требуемое условие, не продолжая выполнение в `/workspace` без ожидаемого mount-а.
- [x] `--ssh` без доступного SSH agent socket завершается до Docker и объясняет, как запустить agent, настроить `SSH_AUTH_SOCK` или отказаться от флага.
- [x] Пустые и отсутствующие значения value-options, включая `--network=` и `--workdir=`, обрабатываются единообразно и проверяются до внешних эффектов.
- [x] Ошибки аргументов и конфигурации выводятся только в `stderr` и всегда сопровождаются ненулевым exit status.
- [x] README и help описывают строгую семантику явно запрошенных режимов.

## Comments

Явные workdir/SSH/network requirements теперь валидируются до Docker. Добавлены точные process-level проверки пустых, отсутствующих и неверных значений, включая защиту от потребления separator как значения.
