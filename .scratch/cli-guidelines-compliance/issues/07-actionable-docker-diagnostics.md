# 07 — Сделать сбои Docker диагностируемыми и ограниченными по времени

**What to build:** при проблеме Docker пользователь быстро понимает категорию сбоя и следующий шаг, а медленная daemon-, context- или image-проверка не выглядит как бесконечное зависание CLI.

**Blocked by:** 01 — Создать строгий process-level контур тестирования CLI.

**Status:** done

- [x] Диагностика различает отсутствие Docker binary, недоступный daemon, проблемы доступа к socket или context и отсутствие локального image.
- [x] Обычный режим показывает краткое actionable-сообщение в `stderr`, а verbose/debug-режим предоставляет исходную безопасную диагностическую причину.
- [x] Подробная диагностика не раскрывает секреты, credentials или чувствительные значения окружения.
- [x] Перед потенциально долгой проверкой интерактивный пользователь получает краткий статус в `stderr`, без загрязнения `stdout` и без анимации в non-TTY режиме.
- [x] Для daemon-, context- и image-операций определена и проверена bounded timeout-политика.
- [x] Контракт локального image или автоматического pull-а выбран явно, отражён в поведении, help и README.
- [x] Каждая категория Docker failure возвращает ненулевой status, а process-level тесты подтверждают потоки и отсутствие ложного успеха.

## Comments

Добавлены bounded daemon/image checks с `JAILBOT_DOCKER_TIMEOUT_SECONDS`, категоризированные actionable errors и безопасный verbose detail. Контракт остаётся local-image-only без автоматического pull.
