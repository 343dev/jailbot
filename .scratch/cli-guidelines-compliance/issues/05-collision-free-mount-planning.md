# 05 — Планировать автоматические mount-ы без коллизий и частичного состояния

**What to build:** перед запуском Docker Jailbot строит целостный и однозначный план автоматических mount-ов, поэтому каждый распознанный host path переводится в существующий container path без duplicate targets и зависимого от порядка частичного состояния.

**Blocked by:** 04 — Передавать контейнерной команде точный argv.

**Status:** done

- [x] Повторные ссылки на один host path всегда используют один и тот же mount и один и тот же container path во всех позициях argv.
- [x] Разные host paths с одинаковым basename получают детерминированные уникальные targets либо вызов завершается до Docker с понятной ошибкой коллизии.
- [x] Mount добавляется в состояние только после полной валидации host path, target path и representability в Docker; отклонённый mount не считается зарегистрированным.
- [x] Для автоматически распознанного path-аргумента действует единая документированная политика ошибки или pass-through без двусмысленного «предупредить и частично продолжить».
- [x] Поведение comma paths, newline paths, `/workspace` paths и escaped paths явно определено, проверено и согласовано с точной передачей argv.
- [x] Любая ошибка планирования возникает до Docker validation и `docker run`.
- [x] README описывает фактическую стратегию targets, дедупликации, коллизий и неподдерживаемых путей.

## Comments

Добавлен файловый реестр mount-плана с lookup по host и target. Повторы переиспользуются, target collisions и непредставимые comma/newline paths фатальны до Docker; `/workspace` и escaped paths остаются явным pass-through.
